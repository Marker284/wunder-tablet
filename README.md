# Wunder Tablet

Подготовка школьных планшетов под Headwind MDM через ADB: ставит MDM-агент,
делает его единственным лаунчером, сносит заводской мусор и приложения,
которые поставили дети, и ведёт таблицу учёта по всему парку.

Писалось под реальный парк из двух десятков планшетов — Xiaomi, Samsung,
Lenovo, Teclast, POCO, Blackview, Android 13–16.

```
┌──────────────────────────────────────────────────────────────┐
│ samsung SM-X216B                                             │
│ серийный SERIAL123456                                         │
├──────────────────────────────────────────────────────────────┤
│ MDM-агент             установлен                             │
│ Владелец (owner)      com.hmdm.launcher/…AdminReceiver       │
│ Кто держит owner      Headwind MDM                           │
│ Google-аккаунт        school01@example.kz                    │
│ Домашний экран        com.hmdm.launcher                      │
├──────────────────────────────────────────────────────────────┤
│ Лаунчеры              удалено 1                              │
│ Браузеры              удалено 2                              │
│ Ассистенты            удалено 3                              │
│ Режим ПК              удалено 1                              │
│ Сторонние (дети)      удалено 1                              │
│ Уведомления           заглушены у 2                          │
└──────────────────────────────────────────────────────────────┘
```

## Три интерфейса, один движок

| Файл | Что это | Когда удобнее |
|---|---|---|
| `launcher_cleanup.py` | CLI, вся логика | скрипты, разовые прогоны, отладка |
| `launcher_tui.py` | полноэкранный TUI (curses) | конвейер: воткнул — вынул — следующий |
| `launcher_gui.py` | окно на PySide6 | когда хочется мышкой |

TUI и GUI импортируют `launcher_cleanup` как модуль — логика не дублируется.

## Что делает

1. **MDM-агент** — ставит `hmdm.apk`, если его нет, выдаёт разрешения
   (`appops`, `pm grant`, `deviceidle`, `netpolicy`), назначает device owner.
2. **Лаунчеры** — находит всё с `category.HOME` и сносит, оставляя MDM
   единственным домашним экраном. Справочник на ~28 заводских лаунчеров.
3. **Браузеры** — сносит всё, что обрабатывает `http/https`, кроме Chrome,
   и назначает его браузером по умолчанию. WebView и обвязка не трогаются.
4. **Ассистенты** — Google Assistant, Gemini, Bixby, ZUI AI, Jovi, Xiao AI
   и ещё два десятка; снимает роль `ASSISTANT` и вызов по кнопке и жесту.
5. **Режим ПК** — десктопные оболочки (Lenovo PC Mode, Motorola Ready For,
   Samsung DeX, Huawei Desktop) плюс системные переключатели вроде
   `zui_pc_mode` и `enter_work_mode_from_keyboard`.
6. **MAC-адрес** — записывает Wi-Fi и Bluetooth MAC, определяет рандомизацию
   (по биту локального администрирования и `useRandomizedMac`) и гасит её
   настройками, доступными через adb.
7. **Сторонние приложения** — всё пользовательское, чего нет в белом списке:
   игры и прочее, что поставили дети. Уведомления у неснесённого глушатся.
8. **Учёт** — строка на планшет в `inventory.csv`: серийник, модель,
   характеристики, аккаунт, что именно снято, ФИО ученика и класс.

9. **Магазины приложений** — находит все магазины и выключает их, включая
   Google Play. Подробнее ниже.

10. **Система** — переводит интерфейс на русский, если стоит другой язык, и
    включает автоматические дату, время и часовой пояс. По ключу
    `--lock-settings` следом закрывает настройки на замок.

Этапы включаются по отдельности: `--only launchers|browsers|assistants|
pcmode|thirdparty|stores|extras|mac|system|accounts`.

## Магазины приложений

Магазин — второй способ поставить игру мимо MDM, поэтому этап `stores`
сначала **показывает**, что есть на планшете, и только потом трогает:

```bash
python3 launcher_cleanup.py --list-stores                # только посмотреть
python3 launcher_cleanup.py --only stores --disable-stores -y
```

```
ПАКЕТ                   НАЗВАНИЕ          ТИП        ВЕРСИЯ  СОСТОЯНИЕ  УВЕДОМЛЕНИЯ  ДЕЙСТВИЕ
──────────────────────────────────────────────────────────────────────────────────────────────────────
com.android.vending     Google Play       системный  47.6.1  работает   разрешены    выключить (снос — только с --include-play)
com.aurora.store        Aurora Store      польз.     4.6.4   работает   разрешены    выключить
com.vendor.secretstore  —                 польз.     1.2.0   работает   разрешены    выключить (не в справочнике)
com.xiaomi.mipicks      GetApps (Xiaomi)  системный  4.71.1  работает   разрешены    выключить
org.fdroid.fdroid       F-Droid           польз.     1.19    отключён   разрешены    уже выключен
```

Магазины ищутся двумя способами: по встроенному справочнику `APP_STORES`
и по интентам — всё, что откликается на `market://`, `appmarket://`,
`mimarket://`, `samsungapps://` или `amzn://`, магазин по определению.
Так находятся вендорские магазины, о которых мы заранее не знали: они
помечаются «не в справочнике». Выключаются они наравне с остальными —
выключение обратимо; а вот для их **сноса** нужен `--force-unknown`.

| Ключ | Что делает |
|---|---|
| — (по умолчанию) | выключить все найденные магазины, включая Google Play |
| `--list-stores` | показать таблицу и выйти, ничего не меняя |
| `--keep-stores` | только показать: этап ничего не выключает |
| `--disable-stores` | то же, что по умолчанию — ключ для явности в скриптах |
| `--enable-stores` | вернуть отключённые магазины обратно |
| `--remove-stores` | снести совсем |
| `--keep-play` | оставить Google Play работающим |
| `--include-play` | разрешить **сносить** Google Play (необратимо) |
| `--stores-catalog-only` | не искать по `market://`, только справочник — быстрее |

**Выключаются все магазины, включая Google Play** и найденные по
`market://` незнакомые. Выключение — это `pm disable-user`: пакет остаётся
на месте и возвращается ключом `--enable-stores`, поэтому тут никаких
исключений не делается. Оставить Play работающим можно ключом
`--keep-play`.

Строгость осталась только у сноса (`--remove-stores`): он необратим, там
Play требует `--include-play` (его снос ломает обновления GMS/WebView), а
незнакомый пакет — `--force-unknown`.

После любого действия состояние перечитывается с планшета — не по тексту
команды, а по `pm list packages`, — и печатается итог по каждому магазину:

```
ПАКЕТ                   НАЗВАНИЕ          БЫЛО      СТАЛО     ИТОГ
────────────────────────────────────────────────────────────────────────
com.android.vending     Google Play       работает  выключен  ✔ ВЫКЛЮЧЕН
com.aurora.store        Aurora Store      работает  выключен  ✔ ВЫКЛЮЧЕН
com.xiaomi.mipicks      GetApps (Xiaomi)  работает  работает  ✖ НЕ ВЫКЛЮЧЕН
org.fdroid.fdroid       F-Droid           выключен  выключен  ✔ ВЫКЛЮЧЕН
```

`✖ НЕ ВЫКЛЮЧЕН` — обычно политика device owner или системный пакет
вендора; такие пакеты попадают ещё и в строку «Магазины не сняты» в
паспорте планшета.

**Побочный эффект выключенного Play:** школьные приложения из
`allowed_apps.txt` перестанут обновляться сами. Обновления в этой схеме
раздаются из консоли Headwind MDM. Если нужны автообновления из Play —
`--keep-play`.

В обычном прогоне (`--auto`, конвейер в TUI) этап выполняется сам и
выключает всё, что нашёл; строка «Магазины» появляется в паспорте планшета
и в таблице учёта.

В TUI это этап «Магазины» плюс строки мастера в разделе «Приложения
детей»; в GUI — отдельная вкладка **«Магазины»**: список с галочками и
кнопки «Показать магазины», «Выключить отмеченные», «Включить обратно»,
«Снести совсем».

## Язык системы и время

Этап `system` приводит планшет к школьному виду:

* **русский интерфейс** — если система работает на другом языке, скрипт
  переключает её на `ru-RU` (ключ `--locale` меняет код, `--no-locale`
  отключает этап). Без root язык меняется не одной командой, поэтому
  отправляются все три способа — `settings put system system_locales`,
  `setprop persist.sys.locale` и интент `SET_LOCALE`, — а результат
  проверяется по `am get-config`, то есть по факту, а не по выводу команд.
  На части прошивок язык применяется только после `adb reboot` — в паспорте
  это видно как «после перезагрузки». Если прошивка не даёт сменить язык
  вовсе, скрипт честно об этом скажет и предложит ручной путь.
* **автоматические дата, время и часовой пояс** — `auto_time=1` и
  `auto_time_zone=1` в global settings, синхронизация по сети
  (`--no-auto-time` отключает). Значения перечитываются с планшета и
  попадают в паспорт и в таблицу учёта.

```bash
python3 launcher_cleanup.py --only system          # только язык и время
python3 launcher_cleanup.py --only system --locale ru-RU --auto
```

Этап идёт **до** аккаунтов и до `--lock-settings` намеренно: блокировка
выставляет `no_config_locale` и `no_config_date_time`, то есть запрещает
менять ровно то, что мы здесь настраиваем.

## Блокировка настроек

* **`--lock-settings`** — блокирует настройки устройства (установку
  приложений, сайдлоад, VPN, сертификаты, дату/время, язык, сброс сети и до
  заводских, безопасный режим) и оставляет доступными **только Wi-Fi и
  Bluetooth**. Bluetooth отдельно не трогается **специально** — детям нужно
  самим подключать клавиатуру и стилус. Выполняется в конце этапа `system`,
  сразу после языка и времени.
* **`--block-stores`** — сносит сторонние магазины (GetApps, Galaxy Store,
  AppGallery, Aurora Store, F-Droid, APKPure и т.п.) прямо в этапе
  `thirdparty`, до таблицы магазинов. Google Play этим ключом не трогается —
  его берёт на себя этап `stores`.

Ограничения ставятся через `dpm set-user-restriction` от имени device
owner. **Важно:** на Android 13+ эта команда у adb-шелла часто недоступна,
а владельцем устройства выступает Headwind MDM, а не adb, — тогда часть
ограничений не применится. Скрипт перечитывает `dumpsys device_policy` и
вслух перечисляет, что не встало; такие политики надёжнее раздавать из
консоли MDM.

Приложения не из `allowed_apps.txt` и без того сносит штатный этап
`thirdparty` (см. «Как решается «дети ставят игры»» ниже) — отдельного
ключа для этого не нужно.

```bash
python3 launcher_cleanup.py --auto --lock-settings --block-stores
```

Оба ключа поддержаны в TUI (раздел «Дополнительно» / «Приложения детей») и
в GUI (вкладка «Ключи»).

## Быстрый старт

```bash
git clone https://github.com/<ваш-аккаунт>/wunder-tablet.git
cd wunder-tablet
cp allowed_apps.example.txt allowed_apps.txt   # свой белый список, опционально
# рядом положите hmdm.apk и папку platform-tools (или поставьте adb в PATH)

python3 launcher_cleanup.py --list     # посмотреть, ничего не трогая
python3 launcher_cleanup.py --list-stores  # какие магазины стоят на планшете
python3 launcher_cleanup.py --only system  # только русский язык и автовремя
python3 launcher_cleanup.py -n         # сухой прогон: показать все команды
python3 launcher_cleanup.py --auto     # полный проход без вопросов
python3 launcher_tui.py                # конвейер с интерфейсом
```

Запускать первый раз лучше с `--list`: он ничего не меняет и показывает,
что нашлось на конкретной модели.

## Конвейер в TUI

Мастер спрашивает этапы, режим и количество планшетов — `0` означает
бесконечно: обработал, попросил сменить планшет, ждёт следующий. Дальше
оператор только втыкает кабели.

```
Сколько планшетов обработать     конвейер (бесконечно)
Автомод (без подтверждений)      да
Ставить MDM, если его нет        да
Вести таблицу учёта              да
Спрашивать ФИО и класс ученика   нет
```

Пунктов в мастере больше, чем строк в терминале, поэтому список
прокручивается: `↑↓` — по одному, `PgUp/PgDn` — страницами, `Home/End` — в
начало и конец. Справа идёт полоса прокрутки, внизу — «пункт N из M».

После каждого планшета рисуется паспорт со сводкой, красными плашками
(нет device owner, нет Google-аккаунта) и подсказкой «отключите планшет».
Паспорт тоже прокручивается теми же клавишами — на низком экране его низ
раньше просто обрезался.

## Как решается «дети ставят игры»

Опора на то, **кто установил приложение**:

```
com.fingersoft.hcr2
   installerPackageName = com.android.vending   ← Google Play
   firstInstallTime     = 2026-09-17 13:53:49   ← сегодня днём
```

* поставлено через `com.hmdm.launcher` → разрешено автоматически;
* есть во встроенном каталоге или в `allowed_apps.txt` → разрешено;
* дата установки `1970` и нет установщика → заводское приложение вендора,
  по умолчанию не трогается (`--remove-preinstalled` сносит и его);
* всё остальное → снести, а уведомления у несносимого заглушить через
  `cmd appops set <pkg> POST_NOTIFICATION ignore`.

Системный раздел в этом этапе не трогается вообще: смотрим только
`pm list packages -3`.

Закрыть сам источник установки через ADB нельзя — это делается на стороне
MDM: device owner выставляет `DISALLOW_INSTALL_APPS`.

## Безопасность

* Трогаются только пакеты, которые реально заявляют `HOME`, обрабатывают
  `http/https` или лежат в пользовательском разделе вне белого списка.
* Жёсткий белый список: MDM, `android`, SystemUI, Settings, WebView,
  `trichromelibrary`, GMS, Play Store, permissioncontroller.
* Незнакомые лаунчеры и браузеры в авторежиме **пропускаются** —
  снести их можно только явным `--force-unknown`.
* Результат каждой команды проверяется по фактическому состоянию пакета,
  а не по тексту вывода: `pm disable-user` отвечает не `Success`, а
  `new state: disabled-user`, и на это уже наступали.
* Домашний экран закрепляется за MDM **до** сноса лаунчеров — иначе
  система не даёт снять текущий домашний экран.
* Без установленного MDM снос лаунчеров не запускается вовсе.
* `--dry-run` показывает все команды, ничего не выполняя.

## Типовые грабли

| Симптом | Причина и что делать |
|---|---|
| `DELETE_FAILED_USER_RESTRICTED` | device owner выставил `no_uninstall_apps`. Скрипт распознаёт это и сам переходит в режим отключения. Снять запрет можно только в консоли MDM |
| `Not allowed to set the device owner because there are already some accounts` | на планшете есть учётные записи. Порядок всегда: сброс → device owner → вход в Google |
| `SecurityException … MANAGE_USERS` | `pm hide`/`pm suspend` закрыты для adb на Android 13+. Это ожидаемо, не ошибка скрипта |
| Панель режима ПК после сноса `ZuiLauncherPC` | её рисует сам SystemUI, гасится настройкой `zui_pc_mode=0`, а автовход с клавиатуры — `enter_work_mode_from_keyboard=0` |
| TUI бесконечно пишет «ожидание планшета» | не найден `adb`. Положите папку `platform-tools` рядом со скриптом |
| Язык остался английским, в паспорте «после перезагрузки» | прошивка применяет `persist.sys.locale` только при старте — `adb reboot` |
| «язык сменить не удалось» | прошивка не даёт менять язык через adb. Вручную: `adb shell am start -a android.settings.LOCALE_SETTINGS` или политикой в консоли MDM |
| Школьные приложения перестали обновляться | это следствие выключенного Google Play. Обновляйте из консоли Headwind MDM или верните Play: `--keep-play` (новые планшеты) / `--enable-stores` (уже настроенные) |

## Таблица учёта

`inventory.csv` — UTF-8 с BOM и разделителем `;`, открывается в Excel
двойным кликом. 34 колонки: дата, серийник, модель, Android, прошивка,
патч, ОЗУ, накопитель, экран, платформа, Wi-Fi MAC, батарея, аккаунт,
владелец, язык, время, магазины, что снято, ФИО ученика, класс.

Колонки можно добавлять безопасно: старые строки просто получат пустые
значения, файл переписывается с новой шапкой.

Дубликаты ищутся по аппаратному серийнику: знакомый планшет обновляет свою
строку, вторая не создаётся, а уже вписанное ФИО не затирается пустотой.

**В репозиторий таблица и логи не попадают** — там персональные данные.
Смотрите `.gitignore`.

## Требования

* Python 3.10+
* `adb` — в `PATH`, рядом со скриптом или в папке `platform-tools`
* для TUI на Windows: `pip install windows-curses`
* для GUI: `pip install PySide6`
* `hmdm.apk` рядом со скриптом, если нужна автоустановка агента

Windows: подробная инструкция в [WINDOWS.md](WINDOWS.md).
